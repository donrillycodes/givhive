What this redesign changes, and why.

Same React components, same routes, same Firebase auth, same Tanstack Query data layer — the redesign is purely visual. Here’s what shifts, and the reasoning behind each move.

1. One brand, top to bottom

Today the landing page is warm and serif-led, then login throws you onto a cooler gray surface in a different typeface. The redesign keeps Plus Jakarta Sans for dense reading (tables, forms, badges) but introduces Fraunces serif for page titles and card headings — the same font that anchors the landing page. The page background shifts from #f4f7f5 to #faf7f0 (the landing’s cream) so logging in feels like stepping into the same building you were just standing outside of.

2. Auth pages stop floating

The current login/register has a 420px-wide brand panel that’s only visible at lg (1024px+), and on standard 1400–1600px laptops the form ends up swimming in white space. The redesign widens the brand panel to 44% (min 420px), adds the landing’s hexagon pattern so the dark side has texture, and widens the form card from max-w-sm to max-w-md with more breathing room. Result: the form has presence at every viewport from 1280 to 1920px.

3. Mobile actually works

Today the dashboard has a mobile sidebar drawer in the code, but no visible trigger to open it. Once you’re on /ngo/updates on a phone, you’re stuck — there’s no nav. The redesign adds a sticky topbar on every dashboard page with a hamburger button on mobile (opens the existing drawer) and a breadcrumb + notification bell on desktop. The same topbar gives mobile users a search affordance and avoids the “header text + huge dead area” problem from the screenshots.

4. The Updates page stops looking broken

The current empty state puts the icon on the left, the title in the middle, and the “Write update” button floating off in the top-right — it reads like three disconnected pieces. The redesign centres the empty state properly (icon, title, copy, CTA all stacked on the centre axis) and turns the Drafts / Published / Archived toggle into a proper pill segmented control so the active state is obvious. Filter pills get a visible count so you know how many items are in each bucket without clicking.

5. Cards lift, edges soften

Cards switch from 0 1px 2px rgba(15,23,42,.04) (almost invisible) to a layered 0 4px 18px rgba(13,46,28,.06), sitting on the cream page instead of fighting against it. Buttons become pill-shaped (border-radius: 9999px) matching the landing, and borders shift to warm #ece6d4 instead of cool #eaf0ec.

6. Nothing changes underneath

Every existing page file stays put. The same Button, StatCard, Badge, FormField components carry the same props and emit the same DOM — they just look different because their internal classes and the design tokens in globals.css change. Routes, queries, mutations, Firebase auth, role guards: untouched.

When you say go, I’ll:

  1. Update globals.css with the new tokens (palette, radii, shadows) and load Fraunces alongside Plus Jakarta Sans.
  2. Refresh the shared components (Button, FormField, Card, StatCard, Badge, EmptyState, FilterPills, Header) so every consumer picks up the new look automatically.
  3. Rebuild AuthShell (BrandPanel + MobileLogo) and add the hex pattern background.
  4. Add a Topbar component and wire it into the (dashboard)/layout.tsx shell — including the mobile hamburger that already has a drawer waiting for it.
  5. Touch up the page bodies only where the redesign needs a layout change (Updates empty state centring, dashboard hero swapping to gradient stat for “Total raised”).

No route changes, no API changes, no breaking functionality. If something here doesn’t feel right, point at it and I’ll adjust before any code ships.
